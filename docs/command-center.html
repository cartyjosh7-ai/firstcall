2
Open the firstcall folder itself in Cursor (or run claude in a terminal there) — not a parent folder, or session memory splits across machines. CLAUDE.md loads full architecture + working log automatically.

Working from another PC — the fine print

Quick steps are in the callout up top

This repo — code, CLAUDE.md, and everything in docs/ — is public and is the entire portable memory: it's what travels via git clone or the ZIP link above, on any machine, no GitHub login needed. Two things do not travel automatically, covered step 3/2 above: .env.local (gitignored — real secrets) and Claude Code's own session history, which is scoped to whichever directory it's launched from, not to the project itself — a session started from a parent folder lands in a different bucket than one started from firstcall/ itself, invisibly breaking continuity. Always launch from firstcall/ directly, on every machine.

Full explanation (why the memory-bucket split happens, exactly what silently degrades if skipped): see "Working from a second machine" in CLAUDE.md.
