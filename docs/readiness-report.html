The one thing that matters most

⚠ firstcallmarketing.ai can't be recovered — it needs to be replaced

This was misdiagnosed in the first version of this report as a stale deployment. It isn't — checked directly in the Vercel dashboard: the fc-consulting project has a clean, current, Ready Production deployment of master at all times. The GitHub → Vercel pipeline has never been broken.

Neither the GoDaddy account nor that other Vercel account is reachable — the user has never used GoDaddy. The live site looks finished because it's a frozen snapshot from that separate, inaccessible setup, not this codebase — that's why it has pages (/why-first-call, /local-marketing-campaign-services) that don't exist in the current repo, while missing /pricing, /start, and /admin, which do.

The fix is a new domain, not recovery. firstcallconsulting.ai — already the fallback used in the code — is confirmed available: $160 for a 2-year registration via Vercel's own domain purchase, which auto-configures DNS with zero extra steps. As of this snapshot the decision is made; the purchase itself is not done yet.

What's left before the first sale

In order — each step mostly unblocks the next.

  1. Buy firstcallconsulting.ai and connect it
    Confirmed available at $160/2yr via Vercel's own domain purchase (Domains → Buy, inside the fc-consulting project) — buying it there auto-wires the DNS, no separate registrar step. This is the only remaining blocker to a live, correct /pricing and /start — the deployment itself is already fine. See "The one thing that matters most" above for the full story.
    Blocks checkout entirely
  2. Set real production environment variables
    None are set locally, and production is unverified from here — check the Vercel project's Environment Variables directly. At minimum: Stripe secret key + the two Foundation price IDs (create them in the Stripe dashboard first) + webhook secret; Resend API key + a domain-verified sender; LEAD_INBOX; a real NEXT_PUBLIC_MAILING_ADDRESS (CASL requires this on every commercial email — do not send real marketing email without it); UNSUBSCRIBE_SECRET and ADMIN_API_SECRET (both currently fall back to insecure defaults).
    No real payment or email works without this
  3. Stand up the CRM's database
    Separate from the checkout env vars above: create a Postgres database from the Vercel dashboard (Storage → Create Database → Postgres/Neon, connected to this project — auto-injects POSTGRES_URL), set AUTH_SECRET, run npm run db:migrate once, then visit /crm/setup to create the one manager account. Full steps are in CLAUDE.md.
    Blocks the CRM only, not checkout
  4. Point the env vars at the new domain once it's bought
    Set NEXT_PUBLIC_SITE_URL, NEXT_PUBLIC_CONTACT_EMAIL, LEAD_INBOX, and RESEND_FROM in Vercel to match firstcallconsulting.ai — the code already reads all of these from content.ts, so nothing else needs to change for the domain swap to take effect everywhere (links, OG tags, email footers).
  5. Fix the leftover "US" references
    The homepage's structured data (areaServed: "US") and the /markets page headline ("...across the US") still assume a US jurisdiction from before the business was confirmed as Calgary, Alberta, Canada-based. Small fix, real credibility/SEO issue.
  6. Decide: real AI agents, or stay on the free mock engine for now
    Without an ANTHROPIC_API_KEY, every research brief and 90-day plan is rule-based, not written by Claude. The system already protects you here — it won't auto-email a mock report to a paying client, it flags it internally instead — but someone has to notice the flag and manually regenerate the real one. Decide which mode you're launching in and make sure whoever answers the "won" lead notification knows what to do with a mock-flagged report.
  7. Confirm the business side, not just the code
    Not visible from this repository, and not something to guess at: a confirmed registered legal business name/entity, a business bank account, an activated (not test-mode) Stripe account in the right country, GST/HST registration if applicable, and — since the MSA says so itself — actual legal counsel review of the MSA/SOW before the first client signs one.
    Off-code, your call
  8. Run one real end-to-end test
    Once deployed and configured: submit the /start form yourself in Stripe test mode, confirm the webhook fires, a report generates, and the right email lands — before the first real customer's card gets charged.

What doesn't exist yet

Not on the punch list because they're not required for a first sale — but worth knowing they're not there before you promise them to a client.

A website-building tool
There is no software that builds or generates a client website. Foundation's own scope explicitly excludes "custom software builds." If a prospect needs a new site rather than an optimized existing one, that's manual, separately-scoped work today — see the Field Manual for how to handle that conversation.
Real keyword & competitor data
The Research agent's keyword and competitor-gap numbers are explicitly labeled illustrative placeholders — no Ahrefs/Semrush/Google Search Console connection exists. Only the live site audit score is real, measured data.
A lead scraper
The CRM (see above) has a ready-to-use import endpoint for cold leads, but nothing scrapes or sources those leads yet — that pipeline itself doesn't exist.
